# Kessoku Ultimate Bocchi Theme

A Claude Code mod (function hooks, Claude Code 2.1.287+; `/bocchi help` names the engine it runs on): a *Bocchi the Rock!*-inspired
charcoal-and-pink skin for **all of Claude Code**, a live **Kessoku Band** agent panel with the
band drawn as **animated pixel-art sprites**, and five themed workflow gags.

![The Kessoku Band on stage, every mood in turn](assets/kessoku-band.gif)

## What it does

| Piece | What you see | How to try it |
| --- | --- | --- |
| Engine theme | The plugin ships `themes/kessoku-bocchi.json`, a real Claude Code theme: pink prompt border and spinner, charcoal diff backgrounds, band colours for success / error / warning / plan mode / permission dialogs, the usage meter, selection, the eight subagent colours and the ultrathink rainbow. On first run Nijika asks once whether to put it on; it is also in `/theme`. | `/bocchi theme on`, `/bocchi theme off` (restores the theme you had), `/bocchi theme` for the state. |
| Skin | Every render site: tool rows framed in pink (edits in a double frame as "setlist" cards with `+a -d` counts), your prompts and Bocchi's replies with a pink bar, folded tool groups marked `♪`, the spinner's verb picked by what the turn is doing (terminal), `Encored for 3s` closing a turn, Bocchi's face on the hint line under the prompt, Nijika heading the question dialog, `♪ kessoku` in the footer, the mod's own command output in a card, and Bocchi's face in the status line: anxious when idle, focused while working, happy when a turn lands, panicking on an error, melting past 85 % context and while `/compact` runs, hiding in the box when interrupted. | Just work. `/bocchi mood panic` tries a face. `/config` → Transcript skin: full / light / none. |
| Pixel-art band | Bocchi, Nijika, Ryo and Kita as pixel-art sprites (v2): 96x96 figures at the density of the reference art, Bocchi's standing pose drawn from it pixel for pixel and the band in the same hand (seven poses, eight faces, box peeks and hair sway each), 32x32 portraits, and a hand-drawn 16x16 mini head each for the terminal. Six moods each (anxious, focused, happy, panic, melting, hiding), each a short loop, the band in step with Bocchi: a breathing idle with nervous glances, strumming with notes rising, a jump with sparkles, shaking with sweat flying, melting into a puddle and back, peeking out of a cardboard box. Every subagent is a **slime** in its member's color, drawn from the user's bead patterns (36x24, Bocchi's with her clips and two faces): bouncing while the act runs (Bocchi wide-eyed), breathing while it waits, asleep with a `z` drifting up once it is done (failed or killed too: the row's red words say why). The art is drawn in `studio/` and animated and rendered with Remotion. In the desktop app (and the editor, and the phone) each sprite is an SVG the surface animates itself, one CSS pixel a pixel; in a terminal the minis are half-block pixels where there is room (16x8 cells, every color) and quadrant blocks in the small spots (8x4), repainted ten times a second with `$.ui.blit`. They stand in the panel's cards, the strip above the prompt, the Blast Radius screen (Bocchi panicking beside her guitar hitting the stage), the Cache Tax warning, Nijika's memo, Replay Theater and the question dialog; the slimes on the cards and in the strip, as an SVG one CSS pixel a pixel, and in a terminal as their 18x12 mini in quadrants (9x3 cells). The status line and toasts take only text, so they keep the kaomoji. | Open `/kessoku`, or `/bocchi demo` to put the band on stage (with acts playing, waiting and done). `/config` → Character art: sprites / kaomoji (no slimes). |
| Kessoku Band panel | A pane with one card per member. Bocchi = the main loop and heavy tasks; Nijika = planning/coordination subagents; Ryo = background, refactors, searches, db, shells; Kita = UI, frontend, docs, edits. The band is also three **subagent types** Claude can delegate to by name, listed beside general-purpose, Explore and Plan: `kessoku-ultimate-bocchi:nijika` (plans, reviews, triage, summaries: a numbered plan or a verdict, edits nothing), `kessoku-ultimate-bocchi:ryo` (searches, shells, tests, lint, "find where X happens": read-only tools plus Bash/PowerShell, short lines back) and `kessoku-ultimate-bocchi:kita` (edits to named files, docs, README, UI copy: Read, Edit, Write, every file she touched listed). Each carries her own prompt and tools, so a Ryo act really is a read-only searcher; the short spelling `kessoku:ryo` works too. Such an act sits on its member's card by name (the toast says "seated by name"); any other subagent is seated by what it was asked, as before. Each card shows the task, context %, tokens, a cost estimate and status, live, plus the plan's fullest rate-limit window. Each subagent's row starts with its slime (in a terminal where the cards are tall; where they are short, a `●` in her color), and a chip on the member's name line counts her slimes on stage. A strip above the prompt shows the four of them (heads in a terminal, four rows), then a row of slimes for the acts on stage (six at most, then `+n`; a finished act sleeps there for half a minute; in a terminal under the heads, when the band has seven rows), "3 slimes on stage (2 playing, 1 waiting)", session cost and the cache's warmth. | `/kessoku` toggles the pane. `/bocchi demo` puts sample acts on stage, `/bocchi demo off` clears them. Ask Claude to "have Ryo find where X happens" and watch the act land on Ryo's card. |
| Cache Tax | When the prompt cache has gone cold, the next send is held once: a panicked warning with the re-write cost (the engine's own estimate after a model switch, else list price at the cache's TTL rate), your prompt is put back in the box, Enter sends it. `/keepwarm` pings the cache with cheap forks shortly before it would lapse and reports when a ping found it already cold. Five minutes before the cache lapses while the session is idle without keepwarm, your notification channel (a toast where there is none) says what the re-write would cost. A compaction resets the tax to the truth: the new transcript has no cache entry yet, the next write is priced at the compacted size, and the panel's `ctx` reads the compacted set, so no stale figure or wrong warning survives `/compact`. | `/bocchi tax` previews the warning. `/cache-tax` shows the state. `/keepwarm 90m`, `/keepwarm 1h30`, `/keepwarm off`. |
| Blast Radius | `rm -rf`, `Remove-Item -Recurse`, `rd /s`, `git reset --hard`, `git clean`, force pushes, `git checkout -- <paths>`, `git restore <paths>`, `find -delete`, `rimraf`, `sh -c "..."`, migrations and infrastructure destroys are held behind the **dropped guitar** screen listing exactly what would go, measured through the engine's own file system (no shell needed). Cancel has focus; Esc cancels; Proceed lets it fall; your notification channel is told what is held while the screen waits. Heredoc bodies, quoted text, comments, dry runs (`git clean -n`, `migrate status`, `-WhatIf`) and a single-file `rm -f` are left alone. The model is told why when it was refused. | `/bocchi crash` previews the screen. Or ask Claude to `rm -rf` a scratch folder. |
| Filetree | The project's files in a pane. A file shimmers pink while Claude edits it, stays pink a while, and turns neon green when a `git commit` succeeds. Reads glow faintly. | `/filetree`, then let Claude edit and commit something. |
| Reflect | A correction ("no, in this repo we use pnpm") becomes a band memo from Nijika above the prompt, with Save to `./CLAUDE.md`, Global, Edit and Skip. Questions and chatter are left alone; one tiny Haiku call drafts the rule, which lands under the band's heading with the file's own line endings. Claude can also propose a rule itself, through the **memo tool** (`mcp__kessoku-ultimate-bocchi__memo`), when it catches itself breaking a convention: the same card, signed "proposed by Bocchi mid-set" (or the member whose act proposed it), with no Haiku call. A proposal is one sentence under 140 characters or it is sent back with why; a second one waits behind the card on screen; the tool tells Claude the rule is held, and nothing is written until you press Save. Reflect off turns both doors off. | `/bocchi memo` previews it (Save really writes); `/bocchi memo proposed` previews a proposed one. |
| Replay Theater | After a turn with edits, the strip offers Replay and a dim `/replay 3 tracks` sits in the empty prompt box (Tab takes it); `/replay` opens the setlist and steps through each edit as a unified diff with the file's real line numbers, track by track. | `/bocchi setlist` previews it. |

`/bocchi help` lists everything, opening with the mod's version and the engine's (and a word when the engine is older than the mod expects); `/bocchi strip` hides or shows the strip. Typing `/bocchi` or `/keepwarm` lists their next words in the typeahead (`theme`, `mood`, `demo`, … and `30m`, `1h`, `2h`, `off`), and a word typed after them completes.

Three things reach your own notification channel (the one `preferredNotifChannel` names: iTerm2, kitty, Ghostty; the desktop app has none), each titled `Kessoku Band`: the guard holding a command, a set of thirty seconds or more that ended (its edits, or the error it stopped on), and the cache about to go cold. The toasts setting governs them too: `none` silences them.

## Tweaking

Every file hot-reloads on save while the session runs.

- `hooks/lib/palette.ts` — the colors (`PALETTE`), the two engine themes' token maps (`THEME_OVERRIDES`, `THEME_OVERRIDES_LIGHT`), the members' faces and lines per mood (alignment-safe: no combining marks or fullwidth glyphs, padded to one width), the spinner words per mode, the turn-footer words, the guitar art. The files under `themes/` are those maps written out for the engine; after editing a map, `npm run themes` in `studio/` rewrites them (and `npm run themes -- --check`, which `npm run check` runs too, fails when they drift).
- `hooks/lib/typeahead.ts` — what the typeahead offers after `/bocchi` and `/keepwarm` (the sub-commands, their arguments, the durations, each with its one-line description).
- `hooks/lib/engine.ts` — the engine version the mod expects (`MIN_ENGINE`), how versions compare, and the features that switch themselves off when a call is missing on the running engine (the hooks cannot be gated: an engine that does not know an event refuses the whole module at load).
- `hooks/lib/band.ts` — the band's agent types (`BAND_AGENTS`: each one's when-to-delegate line, prompt and tools), how a type seats by name (`seatOf`), which keywords send any other subagent to Nijika / Kita / Ryo, which tools belong to whom, which state an act's slime shows for its status (`slimeState`), the price table behind the cost estimates (list prices for the Claude 5 and 4 families, **not your bill**), formatters.
- `hooks/lib/reflect.ts` — what reads as a correction, the prompt that drafts its rule, the memo tool's description and the check a proposed rule passes (`checkRule`), and how a rule lands in a CLAUDE.md.
- `hooks/lib/blast.ts` — the quote-aware shell splitter, the Bash and PowerShell risk classifiers, the dry-run exceptions.
- `hooks/register.tsx` — the hooks and every drawing (`drawPanel`, `drawStrip`, `drawBlast`, `drawCacheTax`, `drawMemo`, `drawReplay`, `drawTree`), `drawSprite` (a Raster on the terminal, an animated Svg elsewhere) with the sprite clock that repaints the terminal's Rasters, and the render hooks for the engine's own sites.
- `hooks/lib/sprite.ts` — playing the sprites: the run-length decoder (`=` runs copy the frame before, so frames decode in order), which frame shows when, the terminal encoder (half blocks or quadrants), and the SVG writer, which draws a loop in layers (what every frame shares once, what clusters of like frames share once, then each frame only what is left) so a 96x96 loop fits the Svg element, merging frames only if a drawing would still run over. `hooks/lib/sprites.gen.ts` is generated by the studio: do not edit it by hand.
- `studio/` — the sprite studio, a Remotion project (Node 20+). `ART-BRIEF.md` is the art direction and `ANIM-BRIEF.md` the timing; `reference/` holds the reference image and its grid, which is Bocchi's stand. The art is palette grids, a folder a member and a file a part (`src/art/members/<member>/`: stand, play, crouch, cheer, panic, box, faces, sway, mini, slime); the mood timelines are in `src/anim/moods.ts` and the slimes' (active, idle, asleep) in `src/anim/slimes.ts`, written as keyframes with holds the way a pixel-art animator keeps an Aseprite file; effects and the 3x5 pixel font are in `src/art/fx.ts`, the melt and the slimes' squash in `src/art/compose.ts`, the guitar crash in `src/anim/crash.ts`. From `studio/` after `npm install`:
  - `npm run dev` opens Remotion Studio on every sprite, slime, contact sheet and the showcase.
  - `npm run check` checks the grids in a second (sizes, palette, the face region identical across poses, the portrait windows holding the face, the slimes on their canvas with Bocchi's two faces on one body), then that `themes/*.json` still match the palette.
  - `npm run themes` writes `themes/kessoku-bocchi.json` and `themes/kessoku-bocchi-light.json` from the palette's token maps (no engine, no render).
  - `node scripts/sheet.mjs <member|all>` renders a contact sheet of every pose, face, frame and slime frame to `out/sheets/`.
  - `npm run sprites` renders every sprite with Remotion and writes `hooks/lib/sprites.gen.ts`, which the running session hot-reloads.
  - `node scripts/terminal.mjs [member]` shows what a terminal draws (the slime minis in quadrants too), through the mod's own encoder, in `out/terminal/`.
  - `node scripts/svg.mjs [member]` writes the SVGs the desktop app draws (the strip's row of slimes too) to a page in `out/svg/`, animating in any browser.
  - `npm run showcase` renders the band on stage to `out/kessoku-band.gif` (the README's GIF lives in `assets/`).
- `/config` → **kessoku-ultimate-bocchi** — the engine theme offer, the transcript skin (full / light / none), character art (sprites / kaomoji), restyling other mods' panels, accent color (a theme key such as `claude`, a hex color or a terminal color name), charcoal backgrounds on/off (skipped on a light theme), which tool rows get cards (all / edits / none; the toasts setting also governs the native notifications), spinner words, the cache TTL the tax assumes when the engine has not said (60 min on a subscription, 5 on an API key), the default keepwarm length, Reflect on/off, panel on start.

Checks: `claude plugin validate <folder>`, `claude plugin test <folder>`, and a type check: `tsc -p <folder>` once the engine has laid `.claude-plugin/types/` beside the mod, or otherwise a `tsconfig.json` kept outside the folder whose `include` names the engine's `claude-code.d.ts` and the mod's `hooks`, `types` and `tests` (the header of that declaration file carries the compiler options).

## Installing it for good

The folder is its own marketplace (`.claude-plugin/marketplace.json`). Copy it somewhere you keep, then in a terminal:

```
claude plugin marketplace add /path/to/kessoku-ultimate-bocchi
claude plugin install kessoku-ultimate-bocchi@kessoku-mods --scope user
```

It then loads in every new session, the desktop app's Code tab included, and its theme is listed in `/theme`. For one session only: `claude --plugin-dir /path/to/kessoku-ultimate-bocchi`. Edits to the folder reach a running session with `/reload-plugins`.

Turn it off with `/plugin` (disable or uninstall), or `claude plugin uninstall kessoku-ultimate-bocchi`. If the Kessoku theme is still selected afterwards, `/theme` picks another; the plugin's copy leaves with it, and a copy written to `~/.claude/themes/` (only where the engine did not list the plugin's) can be deleted there.

## Notes

- A mod is not sandboxed: this one reads the project's file list, runs `git` to measure a held git command, walks the engine's file system to measure a held delete, writes CLAUDE.md only when you press Save, writes a theme copy to `~/.claude/themes/` only when you accept the theme and the engine did not list the plugin's own, switches the `/config` theme row only with your yes, registers three agent types and one tool (`memo`) for the session, and makes one small Haiku call per correction and one cheap fork per keepwarm ping. No network calls of its own.
- Windows: the guard waits for your answer through PowerShell's `Start-Sleep` (no `sleep` binary needed), the PowerShell tool is guarded like Bash, and paths with drive letters and backslashes are compared the way Windows does.
- The Blast Radius classifier is adapted from Anthropic's Blast Radius sample mod (claude-code-playground, Apache-2.0).
- Cost figures are estimates from a price table; `/cost` is the ledger.
- The sprites ship inside the mod as data (`hooks/lib/sprites.gen.ts`); nothing is fetched or rendered at run time. A terminal shows them best with true color; the desktop app animates them in its sandboxed SVG frame (no script runs there). The sprite clock only ticks while a terminal shows a sprite.
- The studio is only for changing the art: the mod never needs `studio/node_modules`, and a copy of the mod for sharing can leave `studio/node_modules` and `studio/out` out.
- Bocchi, Nijika, Ryo and Kita are characters of *Bocchi the Rock!* (Aki Hamaji, Houbunsha / CloverWorks); this is a fan-made, unofficial mod.
